# 22장. 나는 AI와 이렇게 개발했다 — 개발 방법론

이 폴더에는 프로그램이 아니라 **일하는 방식**이 들어 있다. 본보기 넷과 스크립트 둘.

```
본보기 — 복사해서 채운다
  CLAUDE.md.template        지침서. 변하지 않는 것만 적는다
  instruction.template.md   지시문. 대화의 결론을 실행 가능한 문장으로
  handover.template.md      인수인계서. 세션이 바뀌어도 맥락이 이어지게
  commit-convention.md      커밋 메시지 규칙

스크립트 — 실제로 돈다
  snapshot.sh               지침서에서 낡는 부분만 자동으로 갈아 끼운다
  dev_stats.sh              커밋 기록이 무엇을 말하는지 본다
```

## 왜 이 넷인가

22장의 요지는 하나다. **AI가 코드를 썼고, 사람이 맥락을 지켰다.** 그리고 뒤쪽이 훨씬 어려웠다.

맥락을 지키는 데 쓴 장치가 세 가지였다. 지침서, 인수인계서, Git. 이 폴더는 그 셋의 본보기다.

| 파일 | 무엇을 메우나 | 성격 |
|---|---|---|
| 지침서 | 프로젝트가 무엇이고 어디에 무엇이 있는지 | **변하지 않는 것** |
| 지시문 | 이번에 무엇을 바꾸고 무엇을 건드리지 말지 | 한 작업 |
| 인수인계서 | 어제까지 무엇을 했고 다음이 무엇인지 | **지금 이 순간** |
| 커밋 규칙 | 왜 그렇게 고쳤는지 | 영구 기록 |

지침서와 인수인계서를 헷갈리면 둘 다 못 쓴다. 지침서에 "지금 파싱 중" 같은 것을 적으면 다음 주에 거짓말이 되고, 인수인계서에 표 이름을 적으면 매번 다시 써야 한다.

## 해보기

```bash
./dev_stats.sh /경로/내저장소
```

자기 저장소의 커밋 기록을 본다. 월별 막대에서 **빈 달**을 찾아보라. 22장에서 가장 할 말이 많았던 자리가 그것이다. 실제 프로젝트에는 커밋 0건인 두 달이 있었고, 그 두 달이 시스템이 가장 열심히 일한 두 달이었다.

```bash
cp CLAUDE.md.template /경로/내프로젝트/CLAUDE.md   # 채운다
cd /경로/내프로젝트 && /경로/ch22-dev-method/snapshot.sh --dry-run
/경로/ch22-dev-method/snapshot.sh CLAUDE.md
```

`--dry-run` 은 무엇을 쓸지 화면에만 보여 준다. 데이터베이스 현황까지 넣으려면 이렇게.

```bash
PG_DSN=postgresql://user:pw@localhost:5432/db \
SNAPSHOT_TABLES="papers chunks users" \
SNAPSHOT_SERVICES="postgresql mongod docker" \
./snapshot.sh CLAUDE.md
```

## snapshot.sh 가 왜 필요한가

22장에서 확인한 것을 그대로 적는다. 실제 지침서의 "현재 데이터 현황" 절에 3월 날짜가 박혀 있었고, 그 뒤로 데이터가 계속 늘었는데 파일은 7월까지 손대지 않았다. **AI는 지금도 그 파일을 읽고 3월의 숫자를 믿는다.**

지침서는 만드는 순간부터 낡는다. 그것을 지적만 하고 끝내면 반쪽이니, 낡는 부분을 사람 손에서 떼어 냈다.

`snapshot.sh` 는 표시 사이만 갈아 끼운다.

```markdown
<!-- SNAPSHOT:BEGIN -->
   ← 이 안만 자동으로 다시 쓴다
<!-- SNAPSHOT:END -->
```

사람이 쓴 부분(표 이름, 파일 경로, 설계 원칙, 건드리면 안 되는 것)은 건드리지 않는다. 안전장치도 두었다. 결과가 원본의 절반 미만으로 줄면 쓰지 않고 멈춘다. 표시가 없는 파일에는 아무것도 하지 않고 무엇을 넣어야 하는지 알려 준다. 갱신 전 원본은 `.bak` 으로 남긴다.

> ## 4. 건드리지 말 것
> **이 절이 지시문의 절반이다.** 여기 적지 않은 것은 건드려도 된다는 뜻이 된다.

19장에서 도구를 붙이며 배운 것과 같은 이야기다. 무엇을 시킬지 정하는 것보다 **무엇을 시키지 않을지 정하는 것**이 어렵고 중요하다.

## 정직하게

- 이 본보기들은 실제로 쓴 문서를 **뼈대만 남겨 정리한 것**이다. 실제 지침서는 643줄이고 프로젝트 고유의 내용이 대부분이라 그대로 실을 수 없었다.
- `snapshot.sh` 는 **이 책을 쓰면서 만든 것**이다. 지침서가 낡는다는 문제를 확인하고 나서 만들었으니, 실제 프로젝트에서 아홉 달 동안 쓴 도구가 아니다. 그 점은 분명히 적어 둔다.
- 이 저장소에서 자동 검증한 것: 두 스크립트의 문법, `dev_stats.sh` 의 빈 달 탐지(이 저장소의 8월이 실제로 비어 있어 그것으로 확인했다), `snapshot.sh` 의 구간 교체·사람이 쓴 부분 보존·표시 없는 파일 거부·절반 미만 안전장치.
